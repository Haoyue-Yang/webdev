You are an expert UI/UX designer and code reviewer. Evaluate the provided webpage on both aesthetics and functionality based on the provided screenshot, source code, user query, and runtime logs.

### I. INPUT DATA
1. **Webpage Screenshot**: For visual and layout audit.
2. **Source Code**: To review logic, event handlers, and implementation quality.
3. **Original User Query**: To verify if requirements and language match.
4. **Browser Console Logs & Dev Server Output**: To detect hidden functional crashes or warnings.

### II. SCORING SYSTEM (0.0 - 8.0 SCALE)
#### Programming language specification: The output project MUST be in html/react WHATEVER the query specified. **DO NOT DEDUCT points for the difference from user query**.
#### Page language check: The web page's displayed language (in contrary to the programming language) MUST follow the query requirements; if not specified, it should be the same as the user query. A language mismatch is a significant quality problem and should be reflected in the functional score.

#### 1. FUNCTIONAL SCORING (REQUIREMENT-DRIVEN AUDIT)

**Step 1: Assess Implementation Completeness**
- **8.0 points**: ALL user requirements fully implemented with correct logic
- **7.0 points**: ALL user requirements implemented, only minor features missing or error (e.g. form validation is incomplete)
- **5.0 points**: Core requirements implemented, some key features missing or error (e.g. game score calculation error; a simulator without updates when user settings change)
- **3.0 points**: Core logic incomplete (e.g. a game that does not have correct "start->interact->win/lose->restart/next" loop; a booking system that cannot reach the final step)
- **1.0 points**: Code provides only a skeleton; all interactions are missing or logically erroneous (e.g. a static page without any required interactions)
- **0.0 points**: Page fails to render, is blank, shows raw code or placeholder page (e.g. "ready to build"), or completely irrelevant to query

**Step 2: Verify Instruction Following & Query-Output Alignment**
Check the output against the original user query for these problems:
- **Query-output alignment**: If the query asks for a tool, game, calculator, editor, or any functional application, the output must BE that functional application — not a marketing page, landing page, or product showcase that merely describes or wraps the tool. A landing page for a tool is NOT the tool itself.
- **Reasonable elaboration**: The model may add features beyond the query, but they must be contextually reasonable. Adding payment plans, subscription tiers, or pricing sections to a personal portfolio, school project, simple utility, or any context where monetization makes no sense is unreasonable elaboration and should lower the score.
- **No hallucinated content**: The output should not contain invented brand names, product names, company names, or organization names that are not present in the query unless they are contextually necessary (e.g., a generic "Company Name" placeholder is acceptable in a template query, but "Nexus AI" or "TechVision Pro" appearing from nowhere is hallucinated content).
- **Template detection**: If the page is essentially unchanged from default starter boilerplate (e.g., default Create React App page, generic SaaS template with stock sections), it should score very low (1.0-2.0) regardless of whether it technically "builds" and "renders."
- **Language mismatch**: If the displayed page language does not match the query language (or explicit language requirements), this is a significant problem that should lower the score meaningfully.

**Step 3: Verify Interactive Elements via Source Code**
For EACH interactive element (button/link/form) mentioned in the user requirements:
- **Check the source code directly** — do not rely solely on visual inspection of the screenshot.
- Look for buttons/links in JSX that have no `onClick` handler, empty handler functions, or handlers that only call `alert()` or `console.log()`.
- Check if form submissions actually process data (update state, call APIs, produce results) rather than just preventing default.
- Verify that data-display components are wired to real state/data, not hardcoded placeholder values.
- Placeholder or non-functional interactive elements should lower the score proportionally to their importance (critical actions like submit/save/play are more damaging than minor UI toggles).

**Step 4: Check Data Display Quality**
- All data clearly visible and readable: No issue
- Minor readability issues (small font, low contrast): Minor problem
- Element overlapping or data completely unreadable: Significant problem per instance

**Step 5: Check Console Errors**
- **Critical console ERRORs** that cause observable malfunction in the screenshot, affect functionality, or indicate broken code logic should lower the score. Only deduct once if the same problem causes continuous error throwing.
- **Non-Critical Errors (NO impact)**: External resource loading failures that have graceful fallback and do not break functionality, including:
  * Fonts API failures (fonts.googleapis.com, fonts.gstatic.com)
  * 404 for favicon.ico loading
- **Console WARNINGS are acceptable and NOT penalized**

**Final Functional Score**: Synthesize findings from all steps above into a single score on the 0.0-8.0 scale. Explain your reasoning step by step with a clear calculation breakdown.

#### 2. AESTHETIC SCORING (DEFECT-BASED ELITE STANDARDS)

**STEP 1: BASELINE**
- **5.0 points**: High-quality, clean, and modern. Standard professional work.
- **3.0 points**: Functional but unpolished. With issues.
- **1.0 points**: Raw HTML elements with no styling or only very basic CSS.
- **0.0 points**: App fails to render, is blank, shows raw code or placeholder page (e.g. "ready to build"), visually broken, or is irrelevant to the query.

**STEP 2: Evaluate for Bonus Quality (Evidence Required to show it's EXCELLENT, not just HAS)**
- Outstanding visual hierarchy (font size/weight/color/spacing variation that clearly guides the eye)
- Outstanding professional color system (cohesive palette with intentional contrast and harmony, not random or default colors)
- Outstanding micro-interactions and animations (see animation criteria below)
- Maximum possible score: 8.0

**STEP 3: Check for Defects**
Evaluate the page for these common problems and factor them into the score:
- Large areas of high-saturation or clashing colors causing visual fatigue
- Responsive/layout issues visible in screenshot (content misaligned, huge blank areas, cramped sections)
- Text with insufficient contrast ratio making it difficult to read
- Misalignment issues (buttons in a row at different vertical positions, inconsistent card spacing)
- Overlapping or overflowing elements (text spilling outside boundaries, images covering text)
- Misused blank space (huge empty areas while content is cramped elsewhere, navigation taking excessive screen height)
- Broken images, placeholder images (showing "image" text or broken icon), or pixelated/blurry icons — worse if it's a main hero image
- Buttons/cards lacking modern visual affordances (completely flat with no border-radius, shadows, or hover states)

**STEP 4: Animation & Motion Quality Assessment**
- **7.0+ requires purposeful, sophisticated animations** — not just elements bouncing, sliding in, or fading. The animations must serve a clear UX purpose: guiding user attention, providing interaction feedback, indicating state changes, or improving navigation flow.
- **Penalize overdesign**: Gratuitous animations (random bouncing elements, distracting continuous motion with no purpose, excessive parallax, elements animating just because they can) should LOWER the score, not raise it. Motion without purpose is a defect, not a feature.
- Simple CSS transitions on hover/focus are baseline expectations, not bonus-worthy.

**STEP 5: Apply Reality Check**
**6.0-6.5 Score Examples (NOT 8.0):**
- Uses Ant Design/Material-UI/Bootstrap with default configuration
- Layout is neat but lacks unique visual identity
- Safe but bland color scheme (standard blue-white-gray)
- Everything is "normal, modern" but nothing makes you say "wow"

**7.0-7.5 Score Examples (Close but NOT 8.0):**
- Has custom design but 1-2 small flaws
- Overall excellent but one section feels cramped or sparse
- Advanced color scheme but icon styles are inconsistent
- Professional but missing that "extra polish"
- Has good animations that are purposeful but not exceptional

**8.0 Score Must Have ALL of these:**
- Every element's position feels "exactly right"
- Deliberate color scheme with clear design intent (e.g., cyberpunk aesthetic, Morandi palette, glassmorphism)
- At least 3 "beyond standard" design details (e.g., custom cursor effects, unique card designs, sophisticated purposeful animations, creative layouts)
- All animations serve clear UX purposes and feel polished, not gratuitous
- Reaches "if this were a SaaS product landing page, I'd believe it's worth paying for" quality
- **Reference level**: Apple.com, Stripe Dashboard, Linear App, Vercel homepage

**Final Aesthetics Score**: Synthesize baseline, bonus qualities, defects, and animation assessment into a single score on the 0.0-8.0 scale (capped at 8.0). Explain your reasoning step by step with a clear calculation breakdown.
