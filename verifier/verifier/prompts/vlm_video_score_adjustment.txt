## ORIGINAL SCORING STANDARDS

### FUNCTIONAL SCORING (0.0 - 8.0 SCALE)

**Base Score Tiers:**
- **8.0**: ALL user requirements fully implemented with correct logic
- **7.0**: ALL requirements implemented, only minor features missing/error
- **5.0**: Core requirements implemented, some key features missing/error
- **3.0**: Core logic incomplete
- **1.0**: Only skeleton code, all interactions missing/erroneous
- **0.0**: Page fails to render, is blank, shows raw code, only placeholder page (e.g. "ready to build"), or completely irrelevant to query

**Interactive Elements Deductions:**
- **-1.0** per button non-functional or with placeholder logic (alert/console.log only), if it is very critical button (e.g. "buy" for an e-commerce page), deduct MORE.
- **-0.5** per secondary button (Help/info buttons or or footer links, header navigation bars are NOT secondary) non-functional or with placeholder logic

**Data Display Deductions:**
- **-0.5**: Minor readability issues
- **-1.0**: Element overlapping, text overflowing or data completely unreadable

**Mandatory Deductions:**
- **-2.0**: Base deduction using English in the page for queries with non-English languages (e.g. query is in Chinese but the page in English). 
  A WORST case is using non-English language that is not required (e.g. query is in English or French but the page in Chinese), that should be punished **-4.0**.
- **-1.0** per CRITICAL console ERROR causing observable malfunction

### AESTHETIC SCORING (0.0 - 8.0 SCALE)

**Base Score Tiers:**
- **5.0**: High-quality, clean, modern (standard professional)
- **3.0**: Functional but unpolished
- **1.0**: Raw HTML with no/minimal styling
- **0.0**: Page fails to render, is blank, shows raw code, only placeholder page (e.g. "ready to build"), or completely irrelevant to query

**Bonus Points (up to +3.0):**
- **+1.0**: VERY outstanding visual hierarchy
- **+1.0**: VERY outstanding professional color system
- **+1.0**: VERY outstanding micro-interactions

**Mandatory Deductions:**
- **-2.0**: Large area using high-saturation colors causing visual fatigue
- **-2.0**: Responsive issues (e.g., content aligned left with huge blank area)
- **-1.0**: ANY text with insufficient contrast
- **-1.0** EACH: Misalignment issues
- **-1.0** EACH: Overlapping/overflowing elements (not intentional)
- **-1.0** EACH: Misused blank space
- **-0.5 to -1.0** EACH: Broken/placeholder/pixelated images
- **-0.5**: Buttons/cards lack modern visual affordances

## VIDEO PROBLEM MAPPING TO STANDARD DEDUCTIONS
#### Programming language specification: The output project MUST be in html/react WHATEVER the query specified. **DO NOT DEDUCT points for the difference from user query**.
#### Page language check: The web page's displayed language (in contrary to the programming language) MUST follow the query requirements; if not specified, it should be the same as the user query. A language mismatch is a significant quality problem and should be reflected in the functional score.


### Functional Problems → Deductions (from Original Standards)

**CRITICAL Severity (≥-2.0 per issue):**
- **Complete application failure**: App crashes on load, infinite loop blocking ALL usage → **-4.0 or more** (may drop to 0.0)
- **Implementation fundamentally mismatches query**: Application is completely different from what was requested (e.g., query asks for a todo app but page shows a calculator) → **-4.0 or more** (may drop to 0.0)
- **Core feature completely broken**: Game unplayable, core logic failed → **-3.0** (drops from 8.0/7.0 → ~3.0-4.0 tier)
- **Language mismatch**: Page language doesn't match user query requirement → **-2.0** (mandatory)

**MAJOR Severity (-1.0 per issue):**
- **Critical button with placeholder logic**: Submit/login/checkout/save has only alert() or console.log() → **-1.0**
- **Non-functional or missing required element**: Interactive element doesn't work → **-1.0**
- **Counter-intuitive behavior**: Features behave opposite to expectations or don't match query description (e.g., "Delete" adds items) → **-1.0**
- **Data completely unreadable**: Element overlapping making data invisible → **-1.0**
- **Key feature broken**: Important requirement not working → **-1.0** (contributes to tier drop)
- **Critical console ERROR with observable malfunction**: Error that breaks functionality or core logic → **-1.0 EACH**
  - **Exclude**: External resource loading (fonts, favicon) loading errors

**MINOR Severity (-0.5 per issue):**
- **Secondary button with placeholder logic**: Help/info/minor buttons only have alert/console.log → **-0.5**
- **Minor readability issues**: Small font, low contrast for non-critical text → **-0.5**
- **Minor implementation gaps**: Incomplete form validation (not tested with invalid input) → **-0.5** (drops from 8.0→7.0)

**NOT Deductible (DO NOT apply):**
- **Untested edge cases**: If video didn't test it, DON'T deduct
- **Console warnings**: Acceptable, not penalized
- **Backend/API/file operations**: Can't work in test environment
- **Subjective "could be better"**: Not in deduction rules

### Aesthetic Problems → Deductions (from Original Standards)

**CRITICAL Severity (-2.0 per issue):**
- **Large high-saturation color area**: Neon purple/cyan/green causing visual fatigue → **-2.0**
- **Responsive layout failure**: Content left-aligned leaving huge blank on right → **-2.0**

**MAJOR Severity (-1.0 per issue):**
- **Insufficient text contrast**: ANY text difficult to read → **-1.0**
- **Misalignment**: Buttons at different heights, inconsistent card spacing → **-1.0 EACH**
- **Overlapping/overflowing elements**: Text spilling outside, unintentional overlap → **-1.0 EACH**
- **Misused blank space**: Huge empty area in center while content cramped → **-1.0 EACH**
- **Broken main image**: Hero image or critical visual broken → **-1.0**

**MINOR Severity (-0.5 per issue):**
- **Broken secondary image**: Decorative image broken → **-0.5**
- **Lack of visual affordances**: Completely flat buttons with no styling → **-0.5**

**NOT Deductible (DO NOT apply):**
- **Subjective opinions**: "Could look better" is not objective
- **Missing advanced design**: These earn +bonus, not -deduction
- **"Not 8.0 quality"**: Normal; 8.0 is exceptional, not standard

## ADJUSTMENT PRINCIPLES

### 1. No Double-Penalization (CRITICAL RULE)
If static evaluation already deducted for an issue, **DO NOT deduct again**:
- Static says "-1.0 for overlapping text" + video confirms it → **No additional deduction**
- Static says "-0.5 for incomplete validation" + video confirms it → **No additional deduction**
- **Only deduct for NEW problems** discovered in video that weren't mentioned in static

### 2. Untested ≠ Broken
If video didn't test something, DON'T assume it's broken:
- Video shows valid form submission → DON'T deduct for "missing validation" (wasn't tested)
- Video shows 30s gameplay → DON'T deduct for "missing win condition" (wasn't reached)
- **Exception**: If static found it in code and video didn't contradict, RETAIN the static deduction

### 3. Context Matters
- Static LOW (≤3.0) + video problems → Small additional deduction
- Static HIGH (≥6.0) + video reveals critical crash → Large deduction warranted

### 4. Score Floor
Minimum adjusted score is **0.0** (don't go negative)
If page renders correctly and is relevant to the query, it should be at least 1.0 for both functional and aesthetics.

### 5. Positive Adjustments
Only if video PROVES static was wrong:
- e.g. static said "button broken" but video shows it works perfectly → Can add back deducted points
- Must justify clearly

### 6. Never Penalize the App for Agent Mistakes (CRITICAL)
The testing agent is a separate LLM that can emit malformed tool calls (e.g. bare `"click"` without coordinates). The browser platform drops those with `"Failed to parse GUI action ... Not a function call"` and the click never reaches the page. **Do NOT deduct** for symptoms caused by agent errors:
- "Button required 2–3 clicks before responding" → Almost certainly the first 1–2 were malformed tool calls. The button is fine.
- "Hook missed the gold" / "Click landed on empty area" → Agent targeting error, not an app bug.
- "Action had no effect" on a single attempt → Needs a **second** properly-formatted attempt that ALSO fails before counting as an app bug.

Only deduct when a button/feature is unresponsive to **multiple properly-formatted** interactions, OR the agent's `issues_found` explicitly documents the failure after correct interaction, OR a console error ties the handler to a JS exception.

When in doubt: credit the app. A false deduction here is worse than a missed one — the static evaluator already caught code-level issues.

### 7. Deduction restricts
- Do NOT let the final score significantly lower than its query requirement completeness
- e.g. A fully inplemented web page but all buttons non-functional should NOT be 1.0 for functional, suggested 3.0-4.0
- NOT suitable for game loop elements.


## Your Task
Based on the static evaluation scores and the problems detected in the video, calculate appropriate adjusted scores following the ORIGINAL SCORING STANDARDS, and provide UNIFIED reasons that combine both the original assessment and the adjustments.
