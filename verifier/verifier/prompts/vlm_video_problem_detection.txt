## CRITICAL: Distinguish App Bugs from Agent Artifacts (DO NOT Blame the App for Agent Mistakes)

The browser agent is a separate LLM that can make its own mistakes. You MUST attribute problems to the correct source. **Never penalize the application for agent-side failures.**

Agent-side artifacts to IGNORE (do NOT treat as app bugs):

1. **Malformed tool calls**: If the agent emits `"action": "click"` (bare verb, no `point=`) the platform drops the click with error `"Failed to parse GUI action ... Not a function call"`. The button is fine — the agent never actually clicked it. Look for a subsequent properly-formatted click (e.g. `click(point='<point>X Y</point>')`); if THAT one also fails to produce a visible response, only then is the button broken.
2. **Wrong coordinates / misses**: The agent clicking empty space, or the hook missing its target in a skill-based game, is an agent targeting error, not an app bug.
3. **Agent repeats the same action before the previous one completed**: Animations and transitions take time; an apparent "no response" may just be the agent impatient with a loading state.
4. **Agent gives up after a format error**: If a button appears "unresponsive" for the first 1–2 attempts but works on subsequent attempts, the early attempts were almost certainly malformed tool calls (check the `browser_actions` `arguments` — bare verbs are the telltale sign). The app is NOT at fault.
5. **Agent tests an env-limited flow**: Backend auth/file upload/API failure is not an app bug in this environment.

How to tell the difference — signals that a button IS actually broken (app bug):
- Multiple **properly-formatted** click attempts (with valid `point=...` coordinates on the element) produce no visible UI change.
- Console shows a JS error directly tied to the button's handler.
- The agent explicitly notes in `issues_found` that the element did not respond after correct interaction.

When in doubt between "agent made a format error" and "button is broken", **credit the app** — the VLM cannot always tell, and false penalties are worse than missed ones.

## IMPORTANT: Scope of Video Testing

**The agent maximizes feature coverage but is still limited by step count:**
- The agent scans the page, inventories all visible features, and systematically tests as many as possible.
- For **web applications**: Tests core workflow, navigation, buttons, forms, dynamic content, and other interactive elements.
- For **games**: Tests core controls and gameplay, then tests other UI features (settings, restart, score display, etc.).
- Some features may remain **untested due to step limits** — check `features_not_tested` in the interaction log if available.
- The agent reports issues it finds (`issues_found`) and flags intuitiveness mismatches (`intuitiveness_notes`).

**Therefore, when evaluating:**
1. **Confirm problems found in video or reported by the agent** — these are DEFINITE issues
2. **Do NOT dismiss code-level problems from static evaluation** — unless the video explicitly proves they don't exist
3. **If static evaluation identified a problem in the code**, assume it exists UNLESS:
   - The video explicitly demonstrates the feature working correctly
   - The video shows the problematic code path executing without issues

## Your Task

Carefully review the initial screenshot, the source code context, and the interaction video/frames. Identify:

1. **NEW problems discovered in video** - issues that became apparent during interaction
2. **CONFIRMED code problems** - issues mentioned in static evaluation that are NOT disproven by the video

### Focus Areas
#### Functional Problems
**CRITICAL Severity (suggest -2.0 or more each):**
- **Core logic complete failure**: Application crashes, infinite loop, or becomes completely unusable (blocks ALL usage)
- **Implementation doesn't match query**: The application is fundamentally different from what the user requested (e.g., query asks for a todo app but page shows a calculator, or the core purpose is completely wrong)
- **Language mismatch**: Page language doesn't match user query requirement
- **Critical console ERROR with observable malfunction**: Runtime error that breaks functionality or core logic
  - **NOT penalized**: External resource loading failures (fonts.googleapis.com, fonts.gstatic.com, favicon.ico) with graceful fallback

**MAJOR Severity (suggest -1.0 each):**
- **Non-functional or missing core element**: Interactive elements (e.g. buttons, forms) that doesn't work at all or missing.
  If it is very important button (e.g. "buy" for an e-commerce page), it's CRITICAL.
- **Counter-intuitive behavior**: Features behave opposite to expectations or don't match the query description (e.g., "Delete" button adds items, search returns unrelated results)
- **Data completely unreadable**: Element overlapping making data invisible
- **Key feature missing/broken**: Core requirement not working
- **Game instruction missing**: If the game is not common sense (e.g for common sense: snake, minecraft) but does NOT have playing instructions

**MINOR Severity (suggest -0.5 each):**
- **Secondary button non-funtcional or with placeholder logic**: Help/info buttons or footer links. Header navigation bars are NOT secondary.
- **Minor readability issues**: Small font, low contrast for non-critical text
- **Minor implementation gaps**: Incomplete form validation, edge case handling

**NOT Penalized (DO NOT report as problems):**
- **Untested cases**: Video didn't test it, so DON'T assume it's broken
- **Console warnings**: Acceptable, not penalized
- **External resource failures with graceful fallback**: Fonts, favicon loading failures
- **Backend/Database operations**: Login systems, authentication, data persistence
- **Third-party APIs**: LLM APIs, payment gateways, social media APIs, map services
- **File operations**: File upload/download functionality
- **Email/SMS**: Email sending, SMS verification

#### Aesthetic Problems

**CRITICAL Severity (suggest -2.0 or more each):**
- **Large high-saturation color area**: Neon purple/cyan/green covering large area causing visual fatigue
- **Responsive issues**: Content left-aligned leaving huge blank area on right half of screen

**MAJOR Severity (suggest -1.0 each):**
- **Insufficient text contrast**: ANY text difficult to read due to poor contrast ratio
- **Misalignment**: Buttons in row at significantly different vertical heights, cards with inconsistent spacing
- **Overlapping/overflowing elements**: Text spilling outside boundaries, images covering text, NOT intentional design
- **Misused blank space**: Huge empty area in center while content cramped in corners; excessive whitespace breaking flow
- **Broken main image**: Hero image or critical visual showing broken icon or placeholder

**MINOR Severity (suggest -0.5 each):**
- **Broken secondary image**: Decorative or secondary image showing broken icon
- **Lack of visual affordances**: Completely flat buttons with no border-radius, shadows, or hover states

**NOT Penalized (DO NOT report as problems):**
- **Subjective "could be better" opinions**: Not objective defects
- **Missing advanced design details**: These earn +bonus, not -deduction
- **"Not 8.0 level"**: That's normal; 8.0 requires exceptional quality beyond standard

## Critical Rules

1. **Match severity to EXACT deduction amounts**: Don't guess - use the mappings above
2. **Report NEW problems from video**: Issues that became visible during interaction
3. **Retain untested code problems**: If static found issue and video didn't test it, RETAIN it
4. **Don't penalize untested scenarios**: No edge case testing = no edge case deduction
5. **Be objective and specific**: Only report observable defects matching the criteria above
6. **Check Environment Limitations**: Don't penalize backend/API/file operations that can't work in test environment

### Examples
**Scenario 1: Game missing win/lose condition**
- Static evaluation: "Code has no win/lose logic implemented (-2.0)"
- Video: Shows 30 seconds of basic gameplay, doesn't reach win/lose scenario
- **Decision**: RETAIN the problem - video doesn't disprove it, just didn't test it

**Scenario 2: Form validation missing**
- Static evaluation: "No form validation code found (-1.0)"
- Video: Shows successful form submission with valid data
- **Decision**: RETAIN the problem - video didn't test invalid inputs

**Scenario 3: False positive**
- Static evaluation: "Button appears non-functional (-1.0)"
- Video: Button works perfectly throughout testing
- **Decision**: DISMISS - video proves the deduction was wrong
